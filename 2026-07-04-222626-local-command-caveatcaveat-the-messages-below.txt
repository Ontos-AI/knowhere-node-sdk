     Notebook Migration to SDK Parsed-Document Storage

     Context

     docs/new-design.md moves parsed chunk read/sync behavior into the Knowhere
     SDK so Notebook, CLI, and MCP share one model. The SDK side is already 
     built on the current branch (ParsedDocumentStorage interface,
     withParsedStorage, readChunks/grepChunks/getDocumentOutline, resumable
     syncParsedDocument, synchronous assetUrlPolicy:'durable' hardening). This
     plan covers the Notebook side
     (/home/suguan/github.com/ontosAI/knowhere-notebook), which today still uses
     the old path: loadJobResult + the KnowhereAssetStorageOptions adapter,
     plus hand-rolled Blob snapshot readers, a chunk-page cache, and asset
     mirroring.

     The intended outcome: Notebook provides one Vercel-Blob
     ParsedDocumentStorage adapter + an Upstash/QStash-safe scheduler, routes
     all chunk reads/display/chat asset hardening through the SDK, and marks
     sources ready only after parsed storage is synced. Existing remote docs
     remain readable immediately (SDK falls back to remote, backfills Blob in
     the background).

     Decisions taken with the user:
     1. Full rip-and-replace of the hand-rolled snapshot machinery.
     2. Include chat: unify citation/media asset hardening onto the SDK durable
     policy; keep agentic retrieval.query.
     3. QStash-enqueued resumable background sync (reuse the
     deterministic-workflowRunId continuation pattern); parse flow syncs before
     marking ready.

     SDK contract being consumed (no SDK changes)

     - knowledge.withParsedStorage({ storage, scheduler?, limits? }) → new
     configured Knowledge (unwrapped copy).
     - ParsedDocumentStorage (src/types/storage.ts:142):
     readManifest/writeManifest, readChunkPage/writeChunkPage,
     writeAsset/getAssetUrl, readSyncProgress/writeSyncProgress. Reference impl:
     src/storage/disk-parsed-document-storage.ts. Storage is only ever called 
     with {documentId, revisionKey} — never workspace/source.
     - Freshness: manifest is fresh iff manifest.revisionKey === revisionKey,
     where revisionKey = jobResultId ?? jobId. Pass revisionKey into reads to
     hit storage without a remote probe.
     - readChunks(params) — paged (page/pageSize/assetUrlPolicy) cannot combine
     with sectionPath/startChunk/endChunk/chunkId. Never returns zero for a
     ready remote doc (falls back to remote listChunks, returns bounded page,
     fire-and-forget scheduler.schedule to backfill).
     - assetUrlPolicy:'durable' + configured storage → SDK synchronously hardens
     primary assetUrl and metadata.pageAssets[].assetUrl via
     writeAsset/getAssetUrl; on failure omits the URL (never leaks a presigned
     Knowhere URL).
     - syncParsedDocument({documentId, revisionKey}) — resumable via
     sync-progress; bounded by limits; returns completed:false at page/deadline
     bounds (re-invoke to continue); commits manifest only after all pages
     present.

     Implementation

     1. Vercel-Blob ParsedDocumentStorage adapter — 
     src/domains/sources/parsed-document-blob-storage.ts (new)

     class BlobParsedDocumentStorage implements ParsedDocumentStorage,
     constructed workspace-scoped ({ workspaceId, blobStore? }) with an
     injectable blobStore seam (default wraps @vercel/blob get/put/head/del),
     mirroring the seam pattern in
     chunks/server.ts/parse-result-storage-adapter.ts.

     Key layout (documentId-scoped, workspace-rooted — resolves the scoping
     mismatch since one client serves many docs and the adapter only receives
     documentId):
     workspaces/{workspaceId}/parsed-documents/{documentId}/{revisionKey}/manife
     st/current.json
     workspaces/{workspaceId}/parsed-documents/{documentId}/{revisionKey}/chunks
     /page-{N}.json
     workspaces/{workspaceId}/parsed-documents/{documentId}/{revisionKey}/assets
     /{normalizedSourcePath}
     workspaces/{workspaceId}/parsed-documents/{documentId}/{revisionKey}/sync-p
     rogress.json
     - reads → blobStore.get + JSON parse, null on BlobNotFoundError/404 (reuse
     readBlobText). readChunkPage ignores chunkType (SDK filters after read).
     - JSON writes → put(..., {access:"public", allowOverwrite:true, 
     contentType:"application/json; charset=utf-8"}).
     - writeAsset → put(Buffer.from(body), {access:"public", 
     allowOverwrite:true, contentType, multipart:true}) → {sourcePath, url: 
     blob.url}. getAssetUrl → head(key).url or null.
     - Sanitize documentId/revisionKey/sourcePath with a traversal guard (mirror
     DiskParsedDocumentStorage.normalizeRelativeStoragePath: reject ..,
     absolute, empty segments). Keying under {revisionKey} gives the freshness
     contract for free. Chat's existing isNotebookOwnedAssetUrl already treats
     *.blob.vercel-storage.com as owned, so these durable URLs pass through
     un-re-hardened.

     2. Scheduler + sync route

     - src/domains/sources/parsed-document-sync-scheduler.ts (new):
     createQStashSyncScheduler({workspaceId, sourceId, documentId, revisionKey, 
     apiKey}). schedule(task) ignores the closure (can't serialize the client)
     and triggers a QStash continuation, reusing background-reconcile.ts's
     trigger shape: Client.trigger({ url: 
     ${NOTEBOOK_PUBLIC_URL}/api/sources/parsed-sync, body, workflowRunId: 
     ${documentId}-sync-${revisionKey}-${segmentIndex}, retries: 3 }). Add a
     process-level cooldown guard keyed by documentId|revisionKey (like
     lastTriggeredAtBySourceId) so read-path misses don't storm QStash.
     - src/app/api/sources/parsed-sync/route.ts +
     src/domains/sources/parsed-sync-route-workflow.ts (new), modeled on
     source-reconcile-route-workflow.ts: rebuild a parsed-storage knowledge,
     loop context.run("sync-N", () => knowledge.syncParsedDocument({documentId, 
     revisionKey})) until completed:true or budget (~45s / N segments); on
     incomplete trigger continuation segmentIndex+1; on complete for the parse
     flow mark ready (§5); failureFunction writes sync_status='failed' +
     failure_stage='storage_sync' (does not fail an already-ready source — it
     still serves via remote fallback). Partial-snapshot safety is SDK-side.

     3. Client wiring — src/integrations/knowhere.ts

     Add makeKnowhereClientWithParsedStorage(apiKey, { workspaceId, scheduler?, 
     limits? }) → { client, knowledge }. Build the wrapped client via existing
     makeKnowhereClient (keep for retrieval/jobs/documents), then knowledge = 
     client.knowledge.withParsedStorage({ storage: new 
     BlobParsedDocumentStorage({workspaceId}), scheduler, limits }). Invoking
     withParsedStorage through the logging Proxy gives correct this and returns
     a functional unwrapped Knowledge (its internal listChunks won't be logged —
     acceptable). Vercel-safe limits: chunkPageSize:200, remotePageSize:100, 
     maxPagesPerSync:10, maxAssetsPerSync:20, syncDeadlineMs:8000, 
     outlineMaxPages:50, grepMaxPages:50.

     Scoping note: route-chunks reads one source at a time → build per-source
     knowledge with a document-bound QStash scheduler. Chat's multi-doc asset
     loop → build one workspace knowledge with a no-op/coalescing scheduler (its
     reads use synchronous 'durable' hardening; full background sync isn't its
